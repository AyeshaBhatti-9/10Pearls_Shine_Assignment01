# Requirement Analysis Assignment - Online Book Store

## About

This repository contains my Requirement Analysis assignment for the QA internship. The task was to analyze the requirements of an Online Book Store system and document them in a structured, professional format, as if translating business needs into requirements a development and testing team can work with.

## Author

Ayesha Bhatti

## What this document covers

The assignment is divided into the following sections:

1. **Requirement Understanding** - describes the business goal of the system, the different user categories (Guest, Registered, Admin), their expected behaviors, and their typical workflows.
2. **Functional Requirements** - lists what the system must do, covering browsing, searching, cart, checkout, payment, account management, and admin capabilities.
3. **Non-Functional Requirements** - lists the quality attributes of the system, including performance, security, and availability.
4. **User Stories and Acceptance Criteria** - user stories written in the "As a ... I want ... so that ..." format, with acceptance criteria written in Gherkin syntax (Given/When/Then) for each story.
5. **Rough Sprint Planning** - groups the themes into sprints, based on feature dependency, with reasoning for the order chosen.

## How the document is organized

Each section builds on the one before it. The user categories defined in Section 1 are carried forward consistently into the Functional Requirements (Section 2) and into the User Stories (Section 4), so that what a guest or registered user is allowed to do stays the same throughout the document.
